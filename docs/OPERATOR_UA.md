# FALSICORE 0.2.0 — як користуватись

## Одна команда

```bash
bash run.sh
```

(`./run.sh` теж працює, якщо архів розпаковано з правами виконання — наприклад
`unzip`; деякі розпаковувачі цих прав не відновлюють, тому надійна форма —
`bash run.sh`.) Запускай звичайним користувачем, без `sudo`. Потрібні Linux і Python 3.10+;
ставити нічого не треба. Лаунчер перевіряє SHA-256 програми і лише тоді її
запускає. Під час роботи в stderr видно поточну фазу (`[3/8] network: start`).
Якщо фаза триває довше, кожні 10 секунд з'являється рядок `… still running`.
Відсотків і прогнозу часу немає: тривалість перевірок наперед невідома.

Наприкінці термінал покаже:

- **ВИСНОВОК** і що він означає;
- **ЩО ПЕРЕВІРЕНО**: кожна перевірка, її статус, причини неповноти і межі
  обраного режиму;
- **ЩО ЗНАЙДЕНО**: кожна знахідка з пріоритетом P1–P3, тим, про що саме вона
  (назва й ID розширення, батьківський процес, хеш файла), доброякісними
  поясненнями і безпечним наступним кроком;
- шлях до приватного звіту (`dashboard.html`, `report.md`, JSON) і команду
  для тексту, яким можна поділитися.

## Як читати

| Термін | Значення |
|---|---|
| `INDICATOR` | Спостереження, яке треба підтвердити. Не доказ злому. |
| `EXPOSURE` | Можливість або поверхня (широкий дозвіл, відкритий порт). Не намір. |
| `COMPLETED` | Визначену ціль перевірки оглянуто повністю. |
| `PARTIAL` | Ціль оглянуто не повністю. Причина вказана кодом (`TIMEOUT`, `INPUT_TRUNCATED`, `PARSE_UNSUPPORTED`…). |
| Межі scope | Чого цей режим не бачить за задумом: інші облікові записи, root-файли. Вони не роблять перевірку неповною, але й не перевірені. |
| `FAILED` | Збій колектора. Його часткові дані відкинуто. |

`NO_COMPROMISE_INDICATORS_OBSERVED` означає, що в оглянутих даних налаштовані
правила нічого не знайшли. Це **не** сертифікат «комп'ютер чистий».

## Що нового у 0.2.0 для оператора

- Дев'ять перевірок замість восьми: `crossview` порівнює два погляди ядра на
  одне й те саме (перелік процесів проти kill-проби, sysfs проти
  `/proc/modules`, `/proc/net` проти таблиці сокетів, монтування поверх
  `/proc/<pid>`). Розходження — знахідка `HIDDEN_*` з пріоритетом P1.
- Пакети: окрім dpkg підтримано rpm, pacman та apk; правила називаються
  `PACKAGE_*`; `INSECURE_PACKAGE_SOURCE_SETTING` охоплює apt, dnf, pacman, apk.
- Офлайн-образ: `scan --root /mnt/образ --target-user ІМЯ` читає змонтований
  диск; живі перевірки позначено `SKIPPED`, нічого не вигадано.
- Звіт має схему v5; звіти 0.1.3 читаються як LEGACY (хеші перевіряються,
  семантика не перераховується).
- Висновок `INCONCLUSIVE` на звичайному Ubuntu найчастіше через
  `PARSE_UNSUPPORTED` у `~/.bashrc` (`eval "$(…)"` у стандартних рядках):
  аналізатор не вгадує, що робить виконаний результат команди.

## Інші команди

```bash
bash run.sh --profile quick                 # швидкий огляд, без журналів і пакетів
bash run.sh --profile deep                  # плюс перевірка цілісності пакетів (dpkg/rpm/pacman/apk; до кількох хвилин)
python3 -I falsicore.pyz scan --root /mnt/образ --target-user ІМЯ   # офлайн-образ: живі перевірки позначено SKIPPED, не вигадано
python3 -I falsicore.pyz explain ЗВІТ        # повторно прочитати перевірений звіт
python3 -I falsicore.pyz explain --share-safe ЗВІТ   # текст без шляхів, ID і PID
python3 -I falsicore.pyz verify ЗВІТ         # перевірити цілісність звіту
python3 -I falsicore.pyz self-test           # вбудовані тести (~5 с)
```

Ctrl-C зупиняє скан, прибирає запущені ним процеси і повідомляє, яку
незавершену теку не варто вважати результатом. Звіти версії 0.1.2 читаються як
`LEGACY`: хеші перевіряються, але з новими звітами вони не порівнюються.

Системна перевірка (інші облікові записи, root-файли) — окрема свідома дія після
перегляду коду:

```bash
sudo /usr/bin/python3 -I "$PWD/falsicore.pyz" scan --scope system --target-user "$USER" --profile deep
```

## Приватність

Не надсилай `private_index.json`, `findings.json`, cookies або журнали в чат.
Для допомоги використовуй тільки `explain --share-safe`. Сканер нічого не лікує,
не вимикає розширень, не змінює `.bashrc` і не видаляє старих звітів.
